# pipeline-orchestration Specification

## Purpose
Детерминированный контроллер agentflow ведёт change через этапы конвейера, хранит состояние прогона и сам решает о переходах; роли только предлагают артефакты, код и вердикты.

## Requirements

### Requirement: Порядок этапов
Контроллер SHALL выполнять этапы clarify → spec → approval → freeze → apply → acceptance → final → report → human-acceptance → archive, пропуская завершённые, в отдельной ветке `agentflow/<change>` и git worktree.

#### Scenario: Новый run
- **WHEN** выполняется `agentflow run <intent>`
- **THEN** создаётся каталог `.agentflow-runs/<run-id>/`, ветка и worktree, этапы идут по порядку

### Requirement: Состояние и журнал прогона
Контроллер SHALL атомарно вести `state.json` (этап, шаг, findings, гейты, модели, решения, причина остановки) и писать в `events.jsonl` каждое сообщение каждой сессии, решения ACL и гейты.

#### Scenario: Продолжение после остановки
- **WHEN** контроллер убит после этапа (`--inject kill-after:<этап>`) и выполняется `agentflow resume <run-id>`
- **THEN** прогон продолжается с незавершённого этапа, принятые артефакты и батчи не переделываются

### Requirement: Остановка в BLOCKED
Контроллер SHALL останавливать run в BLOCKED с причиной в `state.json` и `ACCEPTANCE.md`, а не продолжать с допущением.

#### Scenario: Изменена замороженная спека
- **WHEN** перед шагом apply digest спеки не совпадает с зафиксированным при freeze
- **THEN** run переходит в BLOCKED с причиной «замороженная спека изменена»

### Requirement: Видимость работы субагентов
Контроллер SHALL печатать каждую петлю с номером раунда, каждый запуск роли (модель, effort, новая или продолженная сессия, время старта), решения ACL, гейты и вердикты, а в конце — сводку пройденных петель. Каждая строка события роли SHALL нести время, когда событие пришло, а итог роли — сводку отказов ACL по причинам с подсказкой, что делать.

#### Scenario: Список субагентов
- **WHEN** выполняется `agentflow agents <run-id>`
- **THEN** выводится строка на каждую сессию CLI: роль, id сессии, запрошенная модель, модель из init и из ответов API

#### Scenario: Время событий роли
- **WHEN** implementer в 14:02:31 вызывает `run_shell_command` с `agentflow-gate unit`
- **THEN** строка этого вызова в логе содержит `14:02:31` сразу после имени роли, а строка `▶ субагент implementer` — время старта сессии

#### Scenario: Сводка отказов в итоге роли
- **WHEN** implementer завершился, а за сессию ACL дважды отклонил `run_shell_command npm test` и один раз запись в `openspec/specs/x/spec.md`
- **THEN** под строкой завершения роли видны две группы отказов с числом повторов, причиной и подсказкой для каждой, а не только `отказов ACL: 3`

#### Scenario: Отказ CLI мимо ACL контроллера
- **WHEN** CLI отклонил вызов `run_shell_command git status` правилом `denyAll`, и контроллер этот вызов не видел
- **THEN** в сводке отказов этот вызов помечен как отклонённый CLI с указанием на `denyAll` policy и настройки CLI

### Requirement: Проверка без моделей
Контроллер SHALL поддерживать `--inject` (точки сбоев, проводящие прогон через каждую петлю) и `--mock` (роли-заготовки задачи slugify демо-проекта). Mock-роли SHALL присылать размышление, как модели в thinking mode: строкой в логе и блоком `thinking` в `events.jsonl`.

#### Scenario: Все петли на mock-ролях
- **WHEN** выполняется `run tasks/01-slugify.md --mock --auto-approve --inject all`
- **THEN** сводка содержит REVISE в петлях артефакта, сквозного ревью, батча и финала, красный гейт, исчерпание лимита и реплику обсуждения вопроса, а change архивируется

#### Scenario: Обсуждение вопроса на mock-ролях
- **WHEN** выполняется `run tasks/01-slugify.md --mock --auto-approve --inject discuss-question`
- **THEN** на первом вопросе с вариантами автопилот задаёт заготовленную реплику, mock-роль отвечает в сессии только на чтение и уточняет описание варианта, затем выбирается рекомендуемый вариант

#### Scenario: Долгое размышление на mock-ролях
- **WHEN** выполняется `run tasks/01-slugify.md --mock --auto-approve --inject think-long:implementer`
- **THEN** первая сессия implementer около 30 секунд присылает размышления раз в секунду, сторож простоя не срабатывает, а run завершается так же, как без этой точки

### Requirement: Панель статуса субагента
Во время `agentflow run` и `agentflow resume` в интерактивном терминале контроллер SHALL держать внизу экрана панель статуса. Лог прокручивается над ней, а панель остаётся на месте. Пока работает субагент, в панели видны его роль, над чем он работает (артефакт и его файл, task batch, вид ревью), модель, effort, новая это сессия или продолжение, время работы, число вызовов инструментов, номер запуска субагента в run и число ролей конвейера.

#### Scenario: Работает субагент
- **WHEN** контроллер запустил implementer с моделью `M` и effort `high` пятым по счёту запуском в run, а в конвейере пять ролей
- **THEN** в нижних строках терминала видны `implementer`, `M`, `high`, время работы, `запуск 5` и `ролей 5`, и они не уходят вверх, пока печатается лог роли

#### Scenario: Над чем работает субагент
- **WHEN** spec-author пишет артефакт `design`, затем spec-reviewer ревьюит его, затем implementer делает task batch 2
- **THEN** панель показывает по очереди `design.md`, ревью `design` и батч `2`, каждый раз рядом с ролью

#### Scenario: Продолжение сессии
- **WHEN** implementer в раунде исправлений продолжает свою сессию через resume
- **THEN** панель отмечает, что сессия продолжена, а не новая

#### Scenario: Номер запуска после resume
- **WHEN** прогон остановлен после шести запусков субагентов и продолжен через `agentflow resume`
- **THEN** первый субагент после продолжения показан в панели как запуск 7

### Requirement: Контекст прогона в панели
Панель статуса SHALL показывать run id, change, текущий этап, текущую петлю с раундом и время с начала текущей команды `run` или `resume`. Когда субагент не работает, вместо его строки панель SHALL показывать, что делает контроллер: последний шаг, гейт, решение человека.

#### Scenario: Петля и раунд
- **WHEN** идёт раунд 2 из 3 петли ревью артефакта `design`
- **THEN** панель показывает этап, имя петли и `2/3`

#### Scenario: Субагент завершился
- **WHEN** роль завершилась и контроллер запускает гейт
- **THEN** строка субагента сменяется строкой контроллера с этим шагом, время роли больше не растёт

### Requirement: Живое время работы
Время работы субагента и общее время run в панели SHALL обновляться не реже раза в секунду, даже если субагент ничего не выводит.

#### Scenario: Модель долго думает
- **WHEN** субагент 30 секунд не присылает сообщений
- **THEN** его время в панели продолжает расти каждую секунду

### Requirement: Панель не мешает диалогам
На время диалога с человеком (выбор из меню, ввод текста) контроллер SHALL убирать панель и выключать режим мыши, а после ответа возвращать их. Меню и ввод при этом работают как без панели и без режима мыши.

#### Scenario: Диалог исчерпания лимита
- **WHEN** открывается диалог выбора после исчерпания раундов
- **THEN** панели на экране нет, меню отрисовано целиком и выбирается стрелками, после выбора панель снова внизу

#### Scenario: Клик во время диалога
- **WHEN** открыт диалог выбора, и человек кликает по строке размышления над меню
- **THEN** размышление не раскрывается, в меню не попадает лишний ввод, и оно по-прежнему выбирается стрелками; после выбора клик по той же строке раскрывает размышление

### Requirement: Когда панель выключена
Контроллер SHALL не включать панель, если stdout не TTY, если терминал ниже 10 строк или уже 40 колонок, если задан флаг `--no-panel` или переменная `AGENTFLOW_NO_PANEL=1`. Без панели лог в консоли и `events.jsonl` остаются прежними, а в stdout не попадают управляющие последовательности панели.

#### Scenario: Вывод в файл
- **WHEN** `agentflow run … --mock --auto-approve` запущен с перенаправлением stdout в файл
- **THEN** в файле нет управляющих последовательностей панели и строк панели

#### Scenario: Флаг отключения
- **WHEN** run запущен в TTY с `--no-panel`
- **THEN** панель не появляется, лог выводится как раньше

### Requirement: Терминал восстанавливается на выходе
При завершении run любым путём SHALL сниматься закрепление нижних строк, панель стираться, курсор оставаться видимым и стоять под последней строкой лога, режим мыши выключаться, а ввод терминала возвращаться в обычный режим: с эхом набранного и Ctrl+C как сигналом. Это SHALL выполняться при успехе, при BLOCKED, при исключении, при Ctrl+C и при выходе через fault injection. Если окно терминала изменило размер, панель SHALL перерисовываться под новый размер.

#### Scenario: Ctrl+C во время работы субагента
- **WHEN** человек нажимает Ctrl+C, пока работает роль
- **THEN** после выхода терминал прокручивается во всю высоту и новый вывод shell не налезает на бывшую панель

#### Scenario: Изменение размера окна
- **WHEN** во время run окно терминала сделали ниже или уже
- **THEN** панель перерисована в нижних строках нового размера, а строки, не влезающие по ширине, обрезаны без переноса

#### Scenario: Выход из режима мыши
- **WHEN** run в режиме мыши завершился успехом, BLOCKED или по Ctrl+C
- **THEN** клик и колесо в терминале снова работают как обычно, набранные в shell символы видны, а Ctrl+C прерывает следующую команду shell

### Requirement: Текущий шаг в панели статуса
Панель статуса SHALL показывать отдельной строкой текущий шаг работающей сессии: ожидание ответа модели, выполнение инструмента с аргументом или работу вложенного субагента. Рядом SHALL быть видны время начала шага и его длительность. Шаг, который длится дольше половины порога простоя, SHALL выделяться предупреждением, а простой — как ошибка. Без субагента эта строка SHALL показывать действие контроллера и время его начала.

#### Scenario: Инструмент выполняется долго
- **WHEN** implementer в 14:02:31 вызвал `agentflow-gate unit`, а результата нет уже 9 минут при пороге простоя 15 минут
- **THEN** строка шага в панели показывает `run_shell_command agentflow-gate unit`, `с 14:02:31` и `09:00`, выделенные как предупреждение

#### Scenario: Ожидание модели
- **WHEN** сессия получила результат инструмента и ждёт следующего ответа модели
- **THEN** строка шага показывает ожидание ответа модели и время с момента получения результата

#### Scenario: Гейт контроллера
- **WHEN** контроллер запустил гейт `unit` после роли
- **THEN** строка шага показывает гейт `unit` и время его старта, пока гейт не завершится

### Requirement: Активные субагенты в панели статуса
Панель статуса SHALL показывать число открытых сессий конвейера и отдельно число вложенных субагентов CLI, вызванных внутри них и ещё не вернувших результат. Сессия SHALL перестать считаться при любом завершении, включая падение CLI и прерывание.

#### Scenario: Вложенный субагент
- **WHEN** implementer вызвал инструмент вложенного субагента CLI, и тот ещё работает
- **THEN** панель показывает одну активную сессию и одного вложенного субагента

#### Scenario: CLI упал без ответа
- **WHEN** CLI роли завершился с кодом 1 без result
- **THEN** счётчик активных сессий в панели возвращается к 0

### Requirement: Отказы ACL в панели статуса
Панель статуса SHALL показывать число отказов ACL текущей сессии и причину последнего, начиная с первого отказа.

#### Scenario: Отказ во время работы
- **WHEN** ACL отклонил implementer вызов `run_shell_command npm test`
- **THEN** в панели видно `отказов ACL 1` и причина отказа, пока сессия работает

### Requirement: Раскрытие размышления по клику
Контроллер SHALL печатать размышление роли блоком: строка с числом символов и под ней начало текста — не больше `--thinking-chars` символов (по умолчанию 300, `AGENTFLOW_THINKING_CHARS`, `0` — без текста). Если текст длиннее, блок SHALL кончаться словом «Развернуть», а в режиме мыши строка SHALL нести пометку `▸`. Клик по такому блоку на экране SHALL раскрывать на месте полный текст со словом «Свернуть» в конце и менять пометку на `▾`. Повторный клик по блоку SHALL сворачивать его обратно к началу текста. Короткое размышление SHALL печататься целиком и не раскрываться. При раскрытии строки лога ниже и панель SHALL оставаться на месте. При сворачивании строки ниже SHALL подниматься, а следующий вывод — печататься сразу под последней строкой лога.

#### Scenario: Раскрыть кликом
- **WHEN** implementer прислал размышление из 1240 символов, блок `▸ размышляет (1240 симв.)` с первыми 300 символами и словом «Развернуть» виден на экране, и человек кликает по «Развернуть»
- **THEN** в блоке весь текст этого размышления и «Свернуть» в конце, строка помечена `▾`, а строки лога под блоком и панель остаются в прежних строках экрана

#### Scenario: Свернуть повторным кликом
- **WHEN** размышление раскрыто, и человек кликает по его строке, по «Свернуть» или по любой видимой строке его текста
- **THEN** в блоке снова начало текста и «Развернуть», строка помечена `▸`, строки лога, бывшие под текстом, поднимаются вплотную к блоку, и следующая строка лога печатается сразу под последней, без пустых строк между ними

#### Scenario: Клик мимо размышления
- **WHEN** человек кликает по строке лога, которая не строка размышления, по пустому месту или по панели
- **THEN** на экране ничего не меняется

#### Scenario: Лог продолжается под раскрытым размышлением
- **WHEN** размышление раскрыто, а роль продолжает работать
- **THEN** новые строки лога печатаются под последней строкой, раскрытый текст прокручивается вверх вместе с логом, и клик по его видимой части сворачивает его

### Requirement: Длинное размышление при раскрытии
Раскрытый текст SHALL занимать не больше строк, чем есть на экране над строкой размышления, чтобы она осталась видна. Если текст длиннее, последней видимой строкой SHALL быть `… ещё N строк — целиком в events.jsonl` с числом скрытых строк в правильной форме. Каждая строка текста SHALL умещаться в ширину окна без переноса терминалом.

#### Scenario: Текст не помещается
- **WHEN** run запущен с `--thinking-chars 0`, строка размышления стоит в 10-й строке экрана, под ней «Развернуть», а текст по ширине окна занимает 40 строк
- **THEN** после клика строка размышления стоит в первой строке экрана, под ней 9 строк текста и строка `… ещё 31 строка — целиком в events.jsonl` со словом «Свернуть», а лог ниже на месте

#### Scenario: Строка у верхнего края
- **WHEN** строка размышления стоит в первой строке экрана, и человек кликает по ней
- **THEN** ничего не раскрывается и на экране ничего не меняется

### Requirement: Режим мыши во время прогона
Во время `agentflow run` и `agentflow resume` контроллер SHALL включать отчёт о кликах мыши, только если stdin и stdout — TTY и не задан флаг `--no-mouse` или переменная `AGENTFLOW_NO_MOUSE=1`. Без режима мыши размышление SHALL печататься строкой `… размышляет (N симв.)` и началом текста без пометок `▸` и `▾`, а в stdout SHALL не попадать управляющие последовательности режима мыши. Ctrl+C в режиме мыши SHALL прерывать run так же, как без него.

#### Scenario: Вывод в файл
- **WHEN** `agentflow run tasks/01-slugify.md --mock --auto-approve` запущен с stdout в файл
- **THEN** размышления в файле — строка `… размышляет (N симв.)` и начало текста без пометок `▸` и `▾` и без слова «Развернуть», а последовательностей включения мыши и ссылок OSC 8 в файле нет

#### Scenario: Флаг отключения
- **WHEN** run запущен в TTY с `--no-mouse`
- **THEN** строка размышления прежняя, клик по ней ничего не раскрывает, а выделение текста мышью и колесо работают как в обычном терминале

#### Scenario: Ctrl+C в режиме мыши
- **WHEN** режим мыши включён, работает роль, и человек нажимает Ctrl+C
- **THEN** run прерывается с тем же кодом выхода и тем же состоянием `state.json`, что и по Ctrl+C без режима мыши

### Requirement: Колесо мыши в режиме мыши
В режиме мыши поворот колеса SHALL выключать перехват мыши на 1 секунду, чтобы следующие повороты колеса прокручивали историю терминала как обычно. Через 1 секунду перехват SHALL включаться снова без действий человека. Обычный клик по размышлению в истории терминала SHALL ничего не менять: клик над историей терминал программе не передаёт. Поэтому в терминале «Развернуть» SHALL быть ссылкой OSC 8 на файл run с полным текстом размышления (`thinking/NNNN-<роль>.md`).

#### Scenario: Прокрутка истории колесом
- **WHEN** во время работы роли человек крутит колесо вверх, чтобы прочитать ранний лог
- **THEN** после первого щелчка колеса история терминала прокручивается колесом, а через секунду клик по строке размышления на экране снова раскрывает её

#### Scenario: Клик вскоре после прокрутки
- **WHEN** человек пролистал историю колесом, вернулся вниз и через 2 секунды после последнего щелчка колеса кликнул по строке размышления на экране
- **THEN** размышление раскрывается

#### Scenario: Клик по строке в истории
- **WHEN** окно терминала пролистано в историю, и человек кликает по размышлению, ушедшему с экрана
- **THEN** на экране ничего не меняется, а клик обрабатывает терминал (выделение текста)

#### Scenario: ⌘-клик по «Развернуть» в истории
- **WHEN** окно терминала пролистано в историю, и человек ⌘-кликает по «Развернуть» размышления, ушедшего с экрана
- **THEN** iTerm2 открывает файл `thinking/NNNN-<роль>.md` каталога run с полным текстом этого размышления

### Requirement: Размышления после диалога и изменения размера окна
Строка размышления, напечатанная до диалога с человеком и видимая на экране после него, SHALL раскрываться кликом. Строки размышлений, напечатанные до изменения размера окна, SHALL после него не раскрываться, потому что терминал заново переносит строки. Размышления, пришедшие после изменения размера, SHALL раскрываться.

#### Scenario: После диалога
- **WHEN** после размышления spec-author открылся и закрылся диалог ревью артефакта, а строка размышления ещё видна на экране
- **THEN** клик по ней раскрывает текст именно этого размышления

#### Scenario: После изменения размера окна
- **WHEN** окно сделали уже после того, как строка размышления напечатана
- **THEN** клик по этой строке ничего не меняет, а строка размышления, пришедшего после изменения размера, раскрывается

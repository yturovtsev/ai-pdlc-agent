# pipeline-orchestration Specification

## Purpose
Детерминированный контроллер agentflow ведёт change через этапы конвейера, хранит состояние прогона и сам решает о переходах; роли только предлагают артефакты, код и вердикты.

## Requirements

### Requirement: Порядок этапов
Контроллер SHALL выполнять этапы clarify → spec → approval → freeze → apply → acceptance → final → report → human-acceptance → archive, пропуская завершённые, в отдельной ветке `agentflow/<change>` и git worktree.

#### Scenario: Новый run
- **WHEN** выполняется `agentflow run <intent>`
- **THEN** создаётся каталог `.agentflow-runs/<run-id>/`, ветка и worktree, этапы идут по порядку

### Requirement: Состояние и журнал прогона
Контроллер SHALL атомарно вести `state.json` (этап, шаг, findings, гейты, модели, решения, причина остановки) и писать в `events.jsonl` каждое сообщение каждой сессии, решения ACL и гейты.

#### Scenario: Продолжение после остановки
- **WHEN** контроллер убит после этапа (`--inject kill-after:<этап>`) и выполняется `agentflow resume <run-id>`
- **THEN** прогон продолжается с незавершённого этапа, принятые артефакты и батчи не переделываются

### Requirement: Остановка в BLOCKED
Контроллер SHALL останавливать run в BLOCKED с причиной в `state.json` и `ACCEPTANCE.md`, а не продолжать с допущением.

#### Scenario: Изменена замороженная спека
- **WHEN** перед шагом apply digest спеки не совпадает с зафиксированным при freeze
- **THEN** run переходит в BLOCKED с причиной «замороженная спека изменена»

### Requirement: Видимость работы субагентов
Контроллер SHALL печатать каждую петлю с номером раунда, каждый запуск роли (модель, effort, новая или продолженная сессия), решения ACL, гейты и вердикты, а в конце — сводку пройденных петель.

#### Scenario: Список субагентов
- **WHEN** выполняется `agentflow agents <run-id>`
- **THEN** выводится строка на каждую сессию CLI: роль, id сессии, запрошенная модель, модель из init и из ответов API

### Requirement: Проверка без моделей
Контроллер SHALL поддерживать `--inject` (точки сбоев, проводящие прогон через каждую петлю) и `--mock` (роли-заготовки задачи slugify демо-проекта).

#### Scenario: Все петли на mock-ролях
- **WHEN** выполняется `run tasks/01-slugify.md --mock --auto-approve --inject all`
- **THEN** сводка содержит REVISE в петлях артефакта, сквозного ревью, батча и финала, красный гейт и исчерпание лимита, а change архивируется

### Requirement: Панель статуса субагента
Во время `agentflow run` и `agentflow resume` в интерактивном терминале контроллер SHALL держать внизу экрана панель статуса. Лог прокручивается над ней, а панель остаётся на месте. Пока работает субагент, в панели видны его роль, над чем он работает (артефакт и его файл, task batch, вид ревью), модель, effort, новая это сессия или продолжение, время работы, число вызовов инструментов, номер запуска субагента в run и число ролей конвейера.

#### Scenario: Работает субагент
- **WHEN** контроллер запустил implementer с моделью `M` и effort `high` пятым по счёту запуском в run, а в конвейере пять ролей
- **THEN** в нижних строках терминала видны `implementer`, `M`, `high`, время работы, `запуск 5` и `ролей 5`, и они не уходят вверх, пока печатается лог роли

#### Scenario: Над чем работает субагент
- **WHEN** spec-author пишет артефакт `design`, затем spec-reviewer ревьюит его, затем implementer делает task batch 2
- **THEN** панель показывает по очереди `design.md`, ревью `design` и батч `2`, каждый раз рядом с ролью

#### Scenario: Продолжение сессии
- **WHEN** implementer в раунде исправлений продолжает свою сессию через resume
- **THEN** панель отмечает, что сессия продолжена, а не новая

#### Scenario: Номер запуска после resume
- **WHEN** прогон остановлен после шести запусков субагентов и продолжен через `agentflow resume`
- **THEN** первый субагент после продолжения показан в панели как запуск 7

### Requirement: Контекст прогона в панели
Панель статуса SHALL показывать run id, change, текущий этап, текущую петлю с раундом и время с начала текущей команды `run` или `resume`. Когда субагент не работает, вместо его строки панель SHALL показывать, что делает контроллер: последний шаг, гейт, решение человека.

#### Scenario: Петля и раунд
- **WHEN** идёт раунд 2 из 3 петли ревью артефакта `design`
- **THEN** панель показывает этап, имя петли и `2/3`

#### Scenario: Субагент завершился
- **WHEN** роль завершилась и контроллер запускает гейт
- **THEN** строка субагента сменяется строкой контроллера с этим шагом, время роли больше не растёт

### Requirement: Живое время работы
Время работы субагента и общее время run в панели SHALL обновляться не реже раза в секунду, даже если субагент ничего не выводит.

#### Scenario: Модель долго думает
- **WHEN** субагент 30 секунд не присылает сообщений
- **THEN** его время в панели продолжает расти каждую секунду

### Requirement: Панель не мешает диалогам
На время диалога с человеком (выбор из меню, ввод текста) контроллер SHALL убирать панель и возвращать её после ответа. Меню и ввод при этом работают как без панели.

#### Scenario: Диалог исчерпания лимита
- **WHEN** открывается диалог выбора после исчерпания раундов
- **THEN** панели на экране нет, меню отрисовано целиком и выбирается стрелками, после выбора панель снова внизу

### Requirement: Когда панель выключена
Контроллер SHALL не включать панель, если stdout не TTY, если терминал ниже 10 строк или уже 40 колонок, если задан флаг `--no-panel` или переменная `AGENTFLOW_NO_PANEL=1`. Без панели лог в консоли и `events.jsonl` остаются прежними, а в stdout не попадают управляющие последовательности панели.

#### Scenario: Вывод в файл
- **WHEN** `agentflow run … --mock --auto-approve` запущен с перенаправлением stdout в файл
- **THEN** в файле нет управляющих последовательностей панели и строк панели

#### Scenario: Флаг отключения
- **WHEN** run запущен в TTY с `--no-panel`
- **THEN** панель не появляется, лог выводится как раньше

### Requirement: Терминал восстанавливается на выходе
При завершении run любым путём SHALL сниматься закрепление нижних строк, панель стираться, курсор оставаться видимым и стоять под последней строкой лога: при успехе, при BLOCKED, при исключении, при Ctrl+C и при выходе через fault injection. Если окно терминала изменило размер, панель SHALL перерисовываться под новый размер.

#### Scenario: Ctrl+C во время работы субагента
- **WHEN** человек нажимает Ctrl+C, пока работает роль
- **THEN** после выхода терминал прокручивается во всю высоту и новый вывод shell не налезает на бывшую панель

#### Scenario: Изменение размера окна
- **WHEN** во время run окно терминала сделали ниже или уже
- **THEN** панель перерисована в нижних строках нового размера, а строки, не влезающие по ширине, обрезаны без переноса

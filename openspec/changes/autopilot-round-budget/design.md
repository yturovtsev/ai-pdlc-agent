# Design

## Context

В `artifactRounds` бюджет раундов (`budget`) меняют четыре места: возврат с ревью человеком
(`toHuman`, ответы на отложенные вопросы), BLOCKED ревьюера, диалог исчерпания (`round + 1`) и возврат
после waiver. Три из них ставят `round + max`, то есть дают полный новый лимит. Человек в этих местах
видит каждый шаг и решает сам. Автопилот выбирает рекомендацию, а она почти всегда «продолжить», так что
цикл ограничивает только третье исчерпание. До исчерпания путь «PASS → вопросы → правка» не доходит
вовсе.

`stageApproval` крутит `for (;;)`: неотвеченные вопросы → `reaccept` → `holisticLoop` → снова
проверка вопросов. Ограничения нет.

## Goals / Non-Goals

**Goals:**
- На автопилоте число ревью артефакта не превышает `artifactRounds`, ревью сквозного — `holisticRounds`.
- Run без автопилота ведёт себя, как раньше.
- Каждый проход по лимиту виден в логе, `state.json` и `ACCEPTANCE.md`, с ключом и значением лимита.

**Non-Goals:**
- Петли кода: правка кода без ревью опаснее правки спеки, гейты не заменяют ревью.
- Новые ключи policy.

## Decisions

### 1. Последняя правка без ревью (`artifactRounds`)

`ctx.human.auto` — автопилот этого run (`--auto-approve` или режим до передачи). На автопилоте
`budget` не меняется. Раунд с находками вызывает `autoNext(round)`: если `autopilotStep(round, budget)`
равен `'final'`, ставится флаг `final` и пишется строка лога. Следующий раунд при `final` — генерация и
валидация. При чистой валидации — `closeLoop(ctx, scope, reason, snap, 'autopilot')`,
`passedBy: 'autopilot'`, запись `loops` с вердиктом `AUTOPILOT`, ревью и `artifactGate` не вызываются.
Ошибка валидации в этой правке ведёт в `artifactExhausted`: артефакт с ошибками `openspec validate`
не пройдёт freeze. Флаг `final` остаётся, поэтому следующий раунд снова без ревью, а диалог
останавливает run на третьем исчерпании.

Почему правка без ревью, а не принятие после последнего REVISE: находки последнего ревью — самая
свежая информация, а одна правка автора стоит меньше нового цикла.

### 2. Сквозное ревью (`holisticRounds`)

На автопилоте при REVISE на раунде `holisticRounds` выполняется `reaccept(groups)` — петли артефактов
со своим лимитом. Затем `closeLoop(…, 'autopilot')` и `holisticPassed` с digest после правок. Диалог
исчерпания не открывается.

### 3. Вопросы без раунда правки (`answerUnapplied`)

Ответ рекомендацией (`Human.question` на автопилоте), `unapplied: true`, решение `autopilot:question`.
Вызывается в трёх местах: после принятия по лимиту — для вопросов этого артефакта; после прохода
сквозного ревью — для всех неотвеченных вопросов; в `stageApproval`, если ответы согласования уже
вносились в этом run (`decisions` с гейтом `approval:question` — переживает resume).

### 4. Учёт

`Proceeded.by: 'autopilot'`. Решение пишется с гейтом `proceed:<петля>` и значением `autopilot-budget`.
`report.ts` делит `proceeded` на решения человека и автопилота. «Режим прогона» считает их отдельно.

### Модули и проверка mock-прогоном

`autopilot.ts`, `controller.ts`, `state.ts`, `report.ts`, `inject.ts`. Mock в копии kit:
`artifactRounds: 1` и `--auto-approve --inject artifact-stuck:specs` дают `artifact:specs: REVISE →
AUTOPILOT`. `holisticRounds: 1` и `--inject holistic-revise` дают `holistic: REVISE → AUTOPILOT`.

## Risks / Trade-offs

- Последняя правка не проверена ревьюером. Риск закрывают разделы `ACCEPTANCE.md`, следующие артефакты
  (их ревьюер читает upstream) и сквозное ревью.
- Минимальный лимит означает, что ответ на вопрос мог не попасть в спеку. Он записан в отчёте,
  человек увидит его на приёмке.
- `--inject artifact-stuck:<id>,proceed:artifact:<id>` на автопилоте больше не проверяет переход
  дальше из диалога исчерпания. Для этого остаётся `blocked:artifact:<id>`.

# Proposal

## Why

На автопилоте (`--auto-approve`, `--auto-until-review`) генерация одного артефакта шла пять и больше
итераций, даже когда в policy стоит `limits.artifactRounds: 1`. Лимит обходят три пути, и ни один не
считает раунды:

- после PASS отложенные вопросы автора и «продуктовые развилки» ревьюера отвечаются рекомендацией и
  уходят автору, а бюджет раундов сбрасывается до полного (`budget = round + max`). Следующий раунд
  порождает новые формулировки вопросов, повтор отсекается только по точному тексту;
- BLOCKED ревьюера с выбором «Дать контекст» тоже сбрасывает бюджет;
- диалог исчерпания на автопилоте берёт «ещё раунд» или «указание» и продлевает лимит на раунд, пока
  с третьего раза не остановит run.

Вопросы, оставшиеся без ответа, задаются ещё раз на согласовании спеки. Их ответы снова запускают
петли артефактов и сквозное ревью, и цикл согласования повторяется, пока модели задают новые вопросы.
В итоге автор и ревьюер порождают друг другу работу без конца, а значение лимита в policy на
автопилоте ни на что не влияет.

## What Changes

Меняется **конвейер agentflow** (`tools/agentflow/`), демо-библиотеку change не трогает.

- **Жёсткий лимит артефакта на автопилоте.** Раунд — правка spec-author, валидация, ревью. После
  ревью номер `artifactRounds` с находками (REVISE, ответы на вопросы после PASS, контекст после
  BLOCKED) автор делает одну последнюю правку. Если валидация OpenSpec чиста, артефакт принимается без
  повторного ревью, и run переходит к следующему артефакту. Если валидация не прошла, открывается
  прежний диалог исчерпания.
- **Жёсткий лимит сквозного ревью на автопилоте.** После раунда номер `holisticRounds` с REVISE
  находки уходят в петли артефактов, затем — согласование спеки без нового сквозного ревью.
- **Вопросы без раунда правки.** Вопросы, на которые правок уже не осталось, автопилот отвечает
  рекомендацией, записывает ответ и автору не отправляет. На согласовании спеки ответы вносятся один
  раз за run.
- **Учёт.** Незакрытые находки таких петель снимаются с причиной, которая называет ключ и значение
  лимита. Переход пишется в `proceeded` с `by: 'autopilot'`, артефакт получает
  `passedBy: 'autopilot'`, вопрос — `unapplied: true`. В `ACCEPTANCE.md` появляются разделы «Пройдено
  автопилотом по лимиту раундов» и «Ответы автопилота, не внесённые в спеку». Диалог «Принять change?»
  называет такие петли.

### Вне scope

- Поведение без автопилота: после лимита по-прежнему решает человек в диалоге исчерпания.
- Петли кода (батч, финальное ревью, acceptance): на автопилоте они продлевают лимит, как раньше, до
  остановки на третьем исчерпании. Пропуск непроверенных правок кода — отдельное решение.
- Сравнение вопросов по смыслу вместо точного текста.
- Отдельный лимит циклов согласования в policy.

### Modified Capabilities

- `spec-phase`: добавляется «Лимит раундов спеки на автопилоте».
- `human-decisions`: меняется «Диалог при исчерпании лимита»: петли спеки на автопилоте диалога
  исчерпания не открывают.

Требование «Автопилот не снимает блокирующие находки» из change `auto-until-review` для петель спеки
уточняется: автопилот по-прежнему не выбирает waiver и «Всё равно перейти дальше» в диалогах, а проход
по лимиту раундов policy выполняет контроллер без диалога.

## Impact

- `autopilot.ts`: `autopilotStep`, `budgetPassReason` — чистые функции для unit-тестов.
- `controller.ts`: `artifactRounds` (последняя правка без ревью, бюджет без продления), `holisticRounds`
  (проход по лимиту), `stageApproval` (ответы вносятся один раз), `closeLoop(…, by)`,
  `answerUnapplied`, строка «Принять change?».
- `state.ts`: `ArtifactState.passedBy: 'autopilot'`, `Proceeded.by`, `Question.unapplied`.
- `report.ts`: разделы автопилота, счётчик в «Режим прогона».
- `inject.ts`: описание `artifact-stuck`. На автопилоте `--inject artifact-stuck:specs,proceed:artifact:specs`
  больше не открывает диалог исчерпания. Переход дальше по артефакту проверяется через
  `blocked:artifact:<id>`.
- README, AGENTS.md, комментарий `limits` в `.agentflow/policy.yaml`.

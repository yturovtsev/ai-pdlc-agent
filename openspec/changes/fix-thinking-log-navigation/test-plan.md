# Test Plan

## Scope

Capability `pipeline-orchestration`, все требования дельты:

- «Согласованная прокрутка интерактивного лога».
- «Позиция чтения при поступлении нового лога».
- «Сохранность лога при изменении размышления».
- «Неизменяемые ссылки на размышления».
- «Жизненный цикл интерактивного окна лога».
- «Когда панель выключена» (MODIFIED).

До freeze нужна сверка с активным `expand-thinking`: новый контракт отменяет ожидание таймера, обрезку длинного раскрытого текста по свободным строкам над блоком и запрет кликов по старым блокам после resize. Эти прежние ожидания не являются oracle для приёмки исправления.

## Environment

- Kit с установленными зависимостями, Node ≥ 22.13. Проверки реализации: `npm run typecheck`, `npm run lint`, `npm run test:agentflow`.
- Acceptance-tester создаёт `e2e/thinking-navigation.test.js`, запускаемый командой `node --import tsx --test e2e/thinking-navigation.test.js`. Тесты используют публичную точку запуска интерактивной терминальной сессии, которую вызывает контроллер, и `log`/`configureThinking` из `tools/agentflow/log.ts`. Точка запуска получает fake TTY, fake stdin и временное хранилище журнала; она должна быть экспортирована из отдельного модуля без импорта `controller.ts`, который запускает main. Интерфейс этой точки фиксируется в реализации и unit-тестах; приёмка проверяет её вывод, не внутренние поля окна.
- Тестовый терминал: сетка 30×120, основной и альтернативный экраны, история основного экрана, изменение размеров, режимы мыши и raw-ввода. Физические события колеса подаются через терминал: если отчёт включён и разрешён — генерируется SGR-ввод; иначе происходит нативная прокрутка его viewport. Клик также зависит от режима, а не безусловно посылается в обработчик. DSR поддерживается для проверки совместимости, но не служит источником ожидаемого положения блока.
- Данные: строки `L0001`…`L0200`, между `L0100` и `L0101` — длинное размышление `spec-author` со строками `T0001`…`T0080`; перед началом интерфейса — маркер shell `BEFORE-RUN`. Каждая строка завершается переводом строки. После L0200 добавить короткое размышление `SHORT-THINKING`, затем длинный блок со строками `TAIL0001`…`TAIL0040`: его свёрнутая кнопка должна быть видна при возврате в конец. Preview — 200 символов, дополнительно прогон с 0. После действий добавлять `AFTER-ACTION`. При проверке ровно одного экземпляра строки считать логические записи и итоговый transcript; последовательные снимки кадров не складывать как новый лог.
- Настройки терминала: mouse reporting разрешён, отчёт колеса разрешён, альтернативный экран разрешён. Сохранение scrollback при status bar проверять в обоих состояниях. Крайние размеры — 10×40 и 8×30. Запрет отчёта колеса — отдельный отрицательный случай с клавишами навигации, а не ожидание недоставляемых mouse events.
- Межпроцессные ссылки: отдельные дочерние Node-процессы импортируют `configureThinking`/`log`, включают TTY-ссылки, пишут разные тексты той же роли в один временный каталог. Из stdout извлекается URL OSC 8, файл читается через стандартный file URL. До второго запуска сохранить bytes и SHA-256 первого файла; добавить старый `0001-spec-author.md`. Повторить в пути с пробелом и `#`.
- Интеграция контроллера: каждый mock-прогон только в новой копии kit с отдельным `git init -b main`, начальным коммитом и доступными установленными зависимостями. Не запускать mock в рабочем kit: он переключает ветку и коммитит. В копии: `node tools/agentflow/bin/agentflow.mjs run tasks/01-slugify.md --mock --auto-approve --inject all`; для PTY и ручного просмотра: `--inject think-long:spec-author --thinking-chars 200`. Run id берётся из вывода и `.agentflow-runs/`; после Ctrl+C — `resume <run-id> --auto-approve`. Повторить с `--no-panel`, с `--no-mouse` и перенаправлением stdout.
- Автоматическая сетка проверяет контракт вывода. Она не доказывает поведение реального iTerm2: ручной прогон обязателен, версия и результаты записываются отдельно. PTY без эмулятора также не проверяет реальное движение viewport.

Дополнительные отрицательные проверки: выключенный mouse wheel reporting не компенсируется фиктивной доставкой событий; PageUp/PageDown/End остаются доступны. Короткое размышление не получает бессмысленного переключения open. После вытеснения старых страниц из кэша первые L-строки читаются из журнала без потерь. Размеры нового окна не используются для попадания клика по кадру до resize. Ошибка записи файла не создаёт ссылку на отсутствующий файл. Потеря возможности cleanup при `SIGKILL` не считается нарушением сценария штатного завершения.

## Evidence

- JSON-снимки: настройки терминала, физические входные события с временем, видимые строки до/после, основной экран после закрытия, логические маркеры и число их вхождений в итоговый transcript.
- Межпроцессные ссылки: URL, имена файлов, SHA-256 до/после, exit codes. Не проверять конкретный UUID или прежнюю нумерацию.
- `e2e/evidence/thinking-navigation.log` — вывод acceptance-команды; `thinking-mock.log` — результат mock-прогона в копии.
- `e2e/evidence/thinking-manual.md` — версия iTerm2/macOS, размеры, состояния разрешения отчёта мыши и scrollback для status bar, результаты каждого ручного шага; при обнаружении рывка — запись экрана или последовательность действий. Автоматические результаты и ручные результаты помечаются раздельно.

## Manual check

1. В iTerm2 с разрешёнными mouse reporting и alternate screen запустить в копии kit `node tools/agentflow/bin/agentflow.mjs run tasks/01-slugify.md --mock --auto-approve --inject think-long:spec-author --thinking-chars 200`. Сделать пять одиночных шагов вверх с паузами больше секунды, быстрый жест и сменить направление: каждый шаг действует, читаемый фрагмент не сбрасывается при новых сообщениях.
2. Вернуться вниз и сразу раскрыть блок первым кликом; прочитать длинный текст прокруткой, свернуть, проверить соседние строки. Прокрутить к раннему размышлению и проверить ссылку ⌘-кликом. Изменить размеры окна и повторить клик.
3. Повторить запуск в новой копии с `--no-panel`. Для обоих вариантов проверить включённую и выключенную настройку «Save lines to scrollback when an app status bar is present»: текст сохраняется, приложение настройки не меняет. После проверки вернуть настройку в исходное состояние.
4. В длинном прогоне нажать Ctrl+C: shell и прокрутка работают, лог и ссылки доступны. Сохранить URL и содержимое старой ссылки, выполнить `resume <run-id> --auto-approve` и убедиться, что старый файл не изменился. Проверить выход по успеху и через диалог остановки.
5. Запустить с `--no-mouse`, затем с перенаправлением в файл: потоковый вывод сохранён. В интерактивном прогоне проверить меню стрелками и возврат позиции чтения. Зафиксировать результаты в `thinking-manual.md`; без реального запуска не отмечать ручную часть пройденной.

# Design

## Context

Мотивация — proposal.md. В ревью воспроизведены две независимые ошибки: пять событий колеса через 1100 мс дают ноль движений истории; два процесса с одним каталогом размышлений записывают один `0001-spec-author.md` и меняют содержимое старой ссылки.

`mouse.ts` включает 1000/1006, поглощает первое событие колеса и выключает 1000 на секунду. `screen.ts` хранит расстояния блоков от курсора, спрашивает DSR и раскрывает блок временной областью DECSTBM. Модель не хранит сам лог. `status-panel.ts` отдельно резервирует три строки. `human.ts` приостанавливает мышь и панель, удерживая `log.ts`. Часть обычного вывода ещё идёт через `console.log` в контроллере и отчёте.

Управляющая последовательность выключения отчёта не возвращает терминалу уже доставленное приложению событие колеса. Настройка iTerm2 [сохранения строк при status bar](https://iterm2.com/3.4/documentation-preferences-profiles-terminal.html) также влияет на временную область раскрытия, даже при `--no-panel`. Поэтому исходная модель не может гарантировать требования простым изменением таймера.

## Goals / Non-Goals

**Goals:** один владелец интерактивного вывода и ввода; логические записи независимо от экранных координат; ограниченный кэш отображения с сохранением всего лога на диске; стабильные ссылки между процессами.

**Non-Goals:** эмуляция произвольных сторонних TUI и импорт существующей истории shell. Границы продукта перечислены в proposal.md.

## Decisions

### 1. Собственное окно истории в альтернативном экране

В режиме мыши `screen.ts` становится рендерером управляемого окна, а новый `log-view.ts` — чистой моделью записей и позиции просмотра. На время интерактивного участка используется альтернативный экран (1049). Основной экран и прежний scrollback shell не перерисовываются. Панель рисуется тем же рендерером в последних трёх строках; DECSTBM и вставка/удаление строк не используются для хранения истории.

Приложение владеет историей текущего интерактивного участка команды: обычные строки, блоки размышлений, итоговые записи диалогов. В начале показывает конец. Вверх и вниз по колесу меняют смещение на одну визуальную строку на доставленное событие. Событие на границе обработано, но не двигает окно за границу. `mouse.ts` непрерывно сообщает колесо с направлением и клики; таймер, `WHEEL_PAUSE_MS` и попытка передать уже полученное событие обратно терминалу удаляются.

Это осознанно заменяет прежний способ навигации: в режиме мыши история принадлежит приложению. Потоковый режим остаётся для `--no-mouse`, переменной окружения и отсутствия TTY. Альтернатива с постоянным включением 1000 и отсутствием обработки колеса блокирует прокрутку; таймер теряет события; обязательная смена профиля iTerm2 не удовлетворяет intent. На режим X10 нельзя полагаться как на универсальное разделение кликов и колеса.

Если пользователь сам запретил отчёт колеса в профиле, приложение не сможет получить эти события. Для этого случая нужны клавиши PageUp/PageDown и End как доступный путь навигации; профили приложение не меняет. Основная приёмка колеса идёт при разрешённом mouse reporting, как и у существующего режима мыши. Работа при терминале, игнорирующем 1049, не заявляется: доступен `--no-mouse`.

### 2. Записи лога и якорь просмотра

Модель хранит стабильные id записей: обычная строка либо блок размышления с полным текстом и состоянием open. Отдельный неизменяемый журнал представления в каталоге run хранит исходные записи в порядке поступления. Его ведёт `RunStore`; он не заменяет `events.jsonl`, который содержит события SDK и решения конвейера, а не весь отображаемый текст. Каждый процесс получает собственный файл журнала, созданный исключительно, чтобы `resume` не затёр прошлый участок.

В памяти остаются индекс записей, их высоты и кэш страниц текста; старые страницы читаются из журнала. Перерисовываются только строки окна и панель. Данные истории не удаляются ради ограничения памяти. При ошибке записи интерактивный участок закрывается, ошибка сообщается через `log.ts`, процесс переходит в потоковый вывод: интерфейс не должен молча выбрасывать строки.

Позиция: `followTail` либо якорь `(id записи, смещение внутри записи)`. Пока `followTail` выключен, новые записи не двигают якорь, а панель продолжает обновляться. При достижении конца колесом вниз или End включается `followTail`. Resize переукладывает строки с тем же логическим якорем; если строка исчезла при сворачивании блока, якорь ограничивается оставшейся частью этого блока.

### 3. Раскрытие как изменение представления

Каждый кадр содержит таблицу соответствия видимых строк id блоков. Клик использует эту таблицу, а не DSR и накопленное расстояние курсора. Между кадрами действие привязано к id блока, показанного в момент получения клика. Клик по панели и обычной строке игнорируется.

Полный текст раскрывается без обрезки по свободному месту над заголовком. Все строки доступны прокруткой, в том числе когда заголовок был у верхнего края. При раскрытии сохраняется якорь на выбранном блоке; при необходимости его заголовок помещается в окно. Сворачивание возвращает preview согласно `--thinking-chars`, сохраняет порядок остальных записей и корректирует якорь. Кнопки «Развернуть» и «Свернуть», цвета и короткие размышления сохраняются. Точное прежнее положение строк под блоком не является инвариантом нового окна: важны отсутствие потерь и доступность текста.

Ссылки OSC 8 используют [поддерживаемый iTerm2 формат](https://iterm2.com/documentation-escape-codes.html). У раскрытого длинного блока сохраняется отдельная ссылка «Полный текст»: иначе после закрытия интерфейса в истории осталась бы только команда сворачивания без доступа к полному содержимому. Потоковый итог всегда содержит preview и ссылку «Развернуть», независимо от последнего состояния блока.

### 4. Неизменяемые файлы размышлений

В `log.ts` вместо локальной порядковой нумерации как идентификатора используется UUID с именем роли. Файл создаётся с эксклюзивным флагом `wx`; при коллизии выбирается другое имя. Ссылка строится через `pathToFileURL`, чтобы пробелы, `#` и другие символы пути не меняли адрес. Старые `NNNN-<роль>.md` не переименовываются и не переписываются; новые файлы сосуществуют с ними.

Сначала фиксируется полный текст, затем печатается ссылка. Ошибка записи не создаёт ссылку на отсутствующий файл; текст остаётся в журнале событий и представлении лога. Новое поле в `state.json` для счётчика не нужно: UUID и эксклюзивная запись безопасны между процессами и после аварии.

### 5. Один жизненный цикл терминала

Новый `terminal-session.ts` управляет входом в альтернативный экран, raw-вводом, подписками, pause/resume и закрытием; `controller.ts` передаёт ему потоки и `RunStore`. Компоненты мыши и панели не вызывают `process.exit` самостоятельно в управляемом режиме. Обычный выход, ошибка, SIGINT и SIGTERM идут через идемпотентную очистку; существующая передача Ctrl+C всей группе процессов сохраняется. Минимальный обработчик `exit` снимает режимы при неожиданном выходе; он не подменяет полноценную очистку с выводом журнала.

`log.ts` — вход обычных и структурированных записей. Нужные вызовы `console.log` контроллера и отчёта переводятся на этот путь. Рисование кадров идёт через внутренний writer терминальной сессии и не попадает обратно в журнал. Не нужно перехватывать и эмулировать произвольный поток ANSI из stdout/stderr: меню и вывод CLI ролей не являются источником кадров лога.

На диалог: удержать новые записи, снять перехват и скрыть панель, передать ввод и отрисовку Inquirer на том же альтернативном экране. После ответа записать семантический итог диалога один раз, восстановить кадр с прежним якорем и состояниями, затем выпустить накопленный лог. Кадры меню не становятся строками истории. Никакого таймера повторного включения мыши нет.

При закрытии: остановить обновления и перехват, снять raw-ввод, восстановить основной экран, затем вывести в него обычное представление накопленного лога ровно один раз, без панели и кадров перерисовки. Итоги диалогов входят в этот вывод однократно. Представление идёт последовательной печатью с полной областью прокрутки; поэтому не зависит от настройки scrollback для status bar. Курсор остаётся под логом. Лимит размера scrollback самого терминала остаётся пользовательским; весь журнал сохраняется на диске. Повторный cleanup ничего не допечатывает.

### 6. Границы модулей и проверка

| Модуль | Изменение | Проверка |
| --- | --- | --- |
| `log-view.ts`, `state.ts` | модель записей, якорь, страницы журнала через RunStore | пронумерованные записи, перемещение и неизменность данных после eviction кэша |
| `screen.ts`, `status-panel.ts` | единый кадр, layout, попадание кликов; обычная панель остаётся для потокового режима | сетка терминала при раскрытии, resize, с панелью и без |
| `mouse.ts` | непрерывные колесо/клики, клавиши навигации, без таймера | физические события проходят через модель доставки терминала |
| `terminal-session.ts`, `human.ts`, `controller.ts`, `report.ts` | жизненный цикл, маршрутизация вывода, меню и cleanup | fake TTY и subprocess/PTY: меню, сигналы, однократный transcript |
| `log.ts` | структурированные блоки, эксклюзивные файлы и file URL | два процесса с одним каталогом, существующие старые файлы, путь с `#` |
| README, AGENTS.md | новый способ навигации, fallback, хранение лога и ссылки | инструкции совпадают с флагами и ручной приёмкой |

Существующий `Vt` не моделирует переключение экранов, viewport и доставку пользовательских событий. Тестовый терминал нужно расширить: основной и альтернативный экран, cursor/scrollback, размеры, режимы отчёта, физические wheel/click → доставка либо нативная прокрутка. Ожидаемый результат — видимый набор строк и сохранность источника, не конкретная последовательность ANSI.

Mock-проверка — только в новой копии kit с `git init` и начальным коммитом, потому что mock переключает ветку и коммитит. Без моделей: `run tasks/01-slugify.md --mock --auto-approve --inject all` для регрессии, `--inject think-long:spec-author --thinking-chars 200` в PTY/iTerm2 для длительного вывода. Последний прогон повторяется с `--no-panel`; прекращение Ctrl+C и последующий `resume <run-id>` проверяют ссылки и восстановление терминала. Полные критерии — test-plan.md.

## Risks / Trade-offs

- Более заметная смена интерактивного интерфейса → сохранить потоковый режим и описать границу: во время работы просматривается лог приложения; shell scrollback доступен после выхода.
- Альтернативный экран может отключаться настройкой терминала → поддерживаемая конфигурация приёмки допускает 1049; `--no-mouse` остаётся обходным путём, профиль не меняется.
- Приложение не получает события, запрещённые профилем → клавиши PageUp/PageDown/End; не утверждать, что отключение отчёта колеса можно исправить парсером.
- Рост лога → журнал на диске, кэш страниц, измерение перерисовки на длинном логе; без скрытого отбрасывания старых записей.
- Изменение размеров во время клика → обновлять таблицу попаданий только вместе с завершённым кадром, действие хранить по id.
- Потеря возможности cleanup при `SIGKILL` → журнал и файлы размышлений уже сохранены; восстановление терминала документировано, обработчик SIGKILL не обещается.
- GUI iTerm2 недоступен автоматическим проверкам → обязательная ручная приёмка на реальном терминале с фиксацией версии и двух вариантов настройки scrollback. Зелёные модульные тесты её не заменяют.

## Migration Plan

1. Реализовать change и проверить потоковый и управляемый режимы. Старые run продолжаются без миграции `state.json`; прежние файлы размышлений сохраняются, новый процесс создаёт новый журнал своего интерактивного участка.
2. Согласовать спецификации до архивирования. `expand-thinking` уже реализован, но ещё активен; его ограничения на таймер колеса, высоту раскрытия и клики после resize противоречат новому поведению. Не архивировать его поверх новых требований без согласования. Сначала синхронизировать его реализованные требования отдельным действием OpenSpec, затем обновить настоящую дельту: новые требования остаются ADDED, а старые «Колесо мыши в режиме мыши», «Длинное размышление при раскрытии», «Размышления после диалога и изменения размера окна» и «Раскрытие размышления по клику» получают полные MODIFIED-блоки с новым контрактом. Сохранить непротиворечащие сценарии preview, флагов, ссылок и Ctrl+C. Это обновление плановых артефактов выполняется до freeze настоящего change; после freeze спека не меняется.
3. На этапе propose основной spec и `expand-thinking` не редактируются и не архивируются. Противоречие зафиксировано явно; standalone `validate` проверяет дельту относительно текущей базы, но не устраняет конфликт активных changes.
4. Откат реализации возвращает потоковый режим (`--no-mouse`) без удаления новых журналов и неизменяемых файлов; возвращать старую перезаписывающую схему имён не нужно.

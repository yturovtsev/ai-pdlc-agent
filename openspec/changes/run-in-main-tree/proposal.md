# Proposal

## Why

Run меняет код и спеку в git worktree, который лежит в его каталоге: `.agentflow-runs/<run>/worktree`.
Работа ролей не видна в основном дереве, пока ветку не влить: смотреть и править её («Исправлю сам»)
приходится в отдельном каталоге внутри каталога прогонов. Отсюда же вторая проблема. Промпт ревьюера
ссылается на контракт `.agentflow/review.schema.json` относительным путём. Этот файл есть только в kit,
а в дереве run целевого репозитория его нет. Роль читает только дерево run и `contexts/` своего прогона,
поэтому схему контракта не находит.

## What Changes

Меняется **конвейер agentflow** (`tools/agentflow/`), демо-библиотеку change не трогает.

- **Run по умолчанию в основном дереве.** `agentflow run` создаёт ветку `agentflow/<change>` от HEAD
  прямо в основном дереве репозитория (`git switch -c`). Правки ролей сразу видны в редакторе, коммиты
  контроллера идут в эту ветку. Логи, контексты, ревью, гейты, размышления и `state.json` остаются в
  `.agentflow-runs/<run>/`.
- **Worktree — флагом.** `--worktree` и пункт «Отдельный worktree» в меню настроек возвращают
  прежнее поведение. Нужен для нескольких run одновременно.
- **Один run на основное дерево.** Lock лежит в каталоге git (`.git/agentflow.lock`). Второй run в том
  же дереве не стартует, а сообщение называет занявший дерево run и предлагает `--worktree`. Lock
  упавшего процесса снимается.
- **Каталог прогонов не попадает в работу ролей.** Запись в `.agentflow-runs/` запрещена всем ролям.
  Проверка границ ACL и проверка целостности перед ревью кода его не учитывают. Если `.agentflow-runs/`
  не в `.gitignore`, контроллер добавляет его в `.git/info/exclude`.
- **Незакоммиченное вне change** не мешает старту. Лог предупреждает: эти правки переходят на ветку
  run и попадут в первый коммит контроллера (freeze спеки).
- **Resume** run основного дерева идёт только на его ветке. Если выбрана другая ветка, resume
  останавливается и говорит, на какую переключиться.
- **Отчёт и итог run** называют основное дерево и шаги merge: вернуться на исходную ветку и влить
  ветку run. Для worktree — merge и `git worktree remove`, как раньше.
- **Контракт ревью доступен ролям.** Контроллер кладёт копию `review.schema.json` kit в `contexts/`
  run. Промпты ревьюеров и acceptance-tester ссылаются на неё абсолютным путём.

### Вне scope

- Автоматический merge и возврат на исходную ветку после приёмки.
- `git stash` чужих правок при старте.
- Запрет ролям читать `.agentflow-runs/` (например, размышления автора). Чтение `contexts/` своего
  run ролям нужно.
- Перенос существующих run между режимами.

### Modified Capabilities

- `pipeline-orchestration`: меняется «Порядок этапов» — основное дерево или worktree. Добавляется
  «Run в основном дереве».
- `target-repo`: меняются «Целевой репозиторий», «OpenSpec репозитория как есть», «Существующий
  change» и «Слои настроек» — дерево run вместо worktree.
- `role-sessions`: меняются «ACL по умолчанию запрещает» и «Сверка изменений после роли» — каталог
  прогонов. Добавляется «Контракт ответа ревью доступен роли».
- `spec-phase`: меняется «Сквозное ревью и freeze» — спека коммитится в ветку run.

## Impact

- Новый `run-tree.ts`: режим дерева, lock, правки вне change, шаги merge — чистые функции для unit-тестов.
- `git.ts`: `currentBranch`, `switchNew`, `branchExists`, `gitPath`, `ensureIgnored`.
- `controller.ts`: `startRun` (основное дерево или worktree, lock, игнор, предупреждение), `resumeRun`
  (ветка, lock), `makeCtx` (копия схемы), `checkBoundary` и проверка целостности без каталога прогонов,
  флаг `--worktree`, итог archive и run только со спекой.
- `roles.ts`: ACL запрещает запись в `.agentflow-runs/`.
- `run-settings.ts`: пункт меню «Отдельный worktree».
- `review-validator.ts`, `context-builder.ts`: путь к схеме в контракте, текст о рабочем каталоге.
- `state.ts`: `options.worktree`, `startBranch`. `report.ts`: ветка, дерево и шаги merge.
- README, AGENTS.md, комментарии `policy.yaml`.

# Proposal

## Why

Роль не может вызвать MCP-инструменты, даже если они перечислены в `tools:` её файла. ACL
контроллера (`decideAcl`) разрешает только запись по glob и `agentflow-gate`. Любой MCP-вызов,
на который CLI спрашивает разрешение, отклоняется с причиной «инструмент не в политике роли»,
а `tools:` для MCP ничего не меняет: `coreTools` CLI фильтрует только встроенные инструменты.

При этом есть дыра в обратную сторону. MCP-инструмент с `readOnlyHint` или с сервера с
`trust: true` CLI 0.1.8 выполняет сам, не вызывая `canUseTool`. Такой инструмент сейчас доступен
любой роли, включая ревьюеров и шаг уточнений «только на чтение», и ACL его не видит. Это
нарушает требование «ACL по умолчанию запрещает».

## What Changes

- Часть репозитория: конвейер agentflow (`tools/agentflow/`), демо-библиотека не меняется.
- В policy роли появляется allowlist MCP-инструментов `roles.<роль>.mcp`: шаблоны имён
  `mcp__<server>__<tool>`, `*` допустим. ACL разрешает MCP-вызов, только если имя совпадает с
  шаблоном роли.
- Роль с пустым `mcp` и любой шаг только на чтение не получают MCP-инструменты вовсе: в сессию
  уходит запрет `mcp__*`, и CLI отклоняет такие вызовы до исполнения независимо от `trust` и
  `readOnlyHint`.
- Роль с непустым `mcp` подключает только серверы, названные в её шаблонах.
- После каждой роли контроллер сверяет её MCP-вызовы с allowlist. Вызов вне allowlist, который
  CLI выполнил без ACL, переводит run в BLOCKED, как файл вне полномочий.
- Диагностика: при старте сессии в логе видны подключённые MCP-серверы и их статус. Если в
  `tools:` роли есть `mcp__…`, которых нет в policy, контроллер предупреждает и называет ключ
  policy.

Вне scope: настройка самих MCP-серверов (берутся из настроек CLI: `.gigacode/settings.json`,
пользовательские), передача `mcpServers` из policy в SDK, MCP в шаге «только на чтение» по
отдельному разрешению, MCP как источник требований для фазы спеки (AGENTS.md, «Не сделано»).

### Modified Capabilities

- `role-sessions`: «ACL по умолчанию запрещает» распространяется на MCP-инструменты; добавляется
  требование «MCP-инструменты по policy» (allowlist, отключение MCP, сверка вызовов после роли,
  диагностика).

## Impact

- Код: `tools/agentflow/roles.ts` (`decideAcl`, опции сессии, учёт MCP-вызовов, лог init),
  `policy.ts` (`RolePolicy.mcp`), `controller.ts` (сверка MCP-вызовов после роли, предупреждение
  при загрузке ролей), `.agentflow/policy.yaml` (`mcp: []` у ролей и комментарий).
- Тесты: `tools/agentflow/agentflow.test.ts`, `tools/agentflow/smoke.ts` (проверка на реальном CLI
  с тестовым stdio MCP-сервером `tools/agentflow/smoke-mcp-server.mjs`).
- Документация: README (policy ролей), AGENTS.md (неочевидные факты о MCP в CLI 0.1.8).
- Совместимость: policy без `mcp` означает «MCP запрещён». Роли, которые сейчас незаметно
  пользуются read-only MCP-инструментами, потеряют их, пока их не разрешат в policy.

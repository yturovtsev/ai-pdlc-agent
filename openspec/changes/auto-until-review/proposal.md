# Proposal

## Why

Сейчас есть два режима: всё решает человек или `--auto-approve` решает всё, включая приёмку и
`openspec archive`. Нужен третий, для прогона без участия (например, на ночь): конвейер сам пишет
спеку и код, закрывает блокирующие находки ревьюеров и останавливается на приёмке change, где
человек проверяет код и решает об archive. `--auto-approve` для этого не годится: он принимает
change без человека и может снять находки critical и major waiver'ом, если автор их оспорил.

## What Changes

Меняется **конвейер agentflow** (`tools/agentflow/`), демо-библиотеку change не трогает.

- **Флаг `agentflow run --auto-until-review`.** Решения человека до приёмки выбирает автопилот:
  уточнение intent и вопросы автора, ревью каждого артефакта, freeze, диалоги исчерпания,
  вмешательство и блокеры. Варианты и рекомендации те же, что у `--auto-approve`. Вместе с
  `--auto-approve` флаг не указывается: run не стартует, сообщение называет оба флага.
- **Автопилот не снимает блокирующие находки.** В этом режиме автопилот никогда не выбирает waiver
  и «Всё равно перейти дальше», даже если они рекомендованы или заданы точкой `--inject proceed:*`.
  Вместо рекомендованного waiver он берёт ещё раунд исправлений; если находки не сходятся, на
  третьем исчерпании рекомендация «Остановить», и run уходит в BLOCKED, как с `--auto-approve`.
- **Парковка на приёмке.** Дойдя до «Принять change?», run пишет `ACCEPTANCE.md`, получает статус
  `awaiting-review` (не BLOCKED) и завершается с кодом 0. Лог называет отчёт, worktree, ветку и
  команду `agentflow resume <run-id>`. Парковка работает и без TTY.
- **Передача решений человеку.** После парковки или остановки run в BLOCKED автопилот этого run
  выключается: `agentflow resume` показывает диалоги человеку. Resume парковки сразу открывает
  «Принять change?»; без TTY run остаётся в `awaiting-review`. После падения или убитого процесса
  resume продолжает с автопилотом.
- **Отчёт и статус.** `ACCEPTANCE.md` получает раздел «Режим прогона»: решения до передачи приняты
  автопилотом, waiver и переходов дальше нет, когда и почему решения перешли к человеку.
  `agentflow status` и `agentflow changes` показывают `awaiting-review`.

### Вне scope

- Парковка в других точках (freeze, диалог исчерпания): там, где автопилот не может продолжить,
  run, как сейчас, останавливается в BLOCKED, а resume ведёт человек.
- Включение и выключение автопилота при `resume` флагом, смена режима посреди run.
- Изменение `--auto-approve`: он по-прежнему решает всё, включая приёмку и waiver.
- Галочка режима в диалоге настроек run из change `run-settings`: этот change даёт только флаг.
- Уведомления о парковке (почта, мессенджеры), merge ветки.

## Impact

- `controller.ts`: флаг `--auto-until-review` и его проверка с `--auto-approve`, парковка в
  `stageHumanAcceptance`, обработка парковки в `pipeline` (статус, код выхода, сообщение),
  передача решений человеку при BLOCKED, resume парковки, автовыбор вместо waiver в
  `artifactExhausted` и сквозном ревью, `status`/`changes` с новым статусом.
- `dialogs.ts`: в режиме автопилот не берёт переход дальше по точке `proceed:*`.
- Новый `autopilot.ts`: режим прогона, включён ли автопилот, выбор автопилота вместо waiver —
  чистые функции для unit-тестов.
- `state.ts`: `options.untilReview`, `handover` (когда и почему решения перешли к человеку),
  статус `awaiting-review`.
- `report.ts`: раздел «Режим прогона» в `ACCEPTANCE.md`, статус парковки в шапке отчёта.
- README и AGENTS.md: режим, парковка, resume.
- Новых зависимостей нет.

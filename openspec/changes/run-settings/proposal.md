# Proposal

## Why

Состав конвейера задаётся только флагами `--auto-approve` и `--no-clarify`, а все пять ролей работают
всегда. Для маленькой правки или прогона, где ревью кода делает человек, приходится ждать
code-reviewer и acceptance-tester или отклонять их вердикты вручную. Выбор нужен перед стартом run,
в одном месте и без запоминания флагов.

## What Changes

Меняется **конвейер agentflow** (`tools/agentflow/`), демо-библиотеку change не трогает.

- **Диалог настроек при `agentflow run`.** В интерактивном терминале перед стартом run показывается
  меню с галочками: пять ролей, «Уточнение intent» и «Автопилот». spec-author и implementer
  отмечены и недоступны: без них нет артефактов и кода. spec-reviewer, code-reviewer и
  acceptance-tester можно снять. Флаги `--no-clarify` и `--auto-approve` задают начальное состояние
  галочек. Enter без изменений — run, как раньше.
- **Выключенная роль — её шаг пропускается:**
  - spec-reviewer — артефакт после детерминированной валидации OpenSpec сразу идёт на ревью
    человеку, сквозного ревью нет, freeze его не требует;
  - code-reviewer — батч принимается по зелёным гейтам, финал — только полные гейты: красные
    исправляет implementer, как в петле батча;
  - acceptance-tester — этапа acceptance нет.
- **Неинтерактивный запуск.** Флаг `--skip-roles <роль,роль>` выключает роли без диалога. Без TTY,
  с `--auto-approve` или с `--skip-roles` диалог не показывается. Обязательную или неизвестную роль
  выключить нельзя: run не стартует, сообщение называет допустимые роли.
- **Настройки прогона** пишутся в `state.json`. `resume` их сохраняет. Лог и `ACCEPTANCE.md` называют
  выключенные роли и пропущенные шаги, панель считает только включённые роли.

### Вне scope

- Выключение spec-author и implementer: артефакты и код человек пишет в своём редакторе и запускает
  `agentflow run --change <id>` для существующего change.
- Изменение настроек при `resume` и посреди run.
- Остальные опции в диалоге: панель, мышь, `--inject`, `--mock`, лимиты раундов — остаются флагами.
- Свои роли сверх пяти стандартных.
- Команды `/opsx:*` и `/spec-*` для gigacode.

### Modified Capabilities

- `pipeline-orchestration`: добавляются «Диалог настроек run», «Выключение ролей без диалога» и
  «Настройки прогона в состоянии и отчёте».
- `spec-phase`: меняются «Петля артефакта» и «Сквозное ревью и freeze» — без spec-reviewer.
- `apply-phase`: меняются «Петля батча», «Acceptance по спеке» и «Финальное ревью» — без code-reviewer
  и acceptance-tester.

## Impact

- `controller.ts`: диалог настроек в `startRun`, флаг `--skip-roles`, пропуск шагов выключенных ролей
  в петлях артефакта, сквозного ревью, батча, acceptance и финала, условие freeze, собеседники
  обсуждения только из включённых ролей.
- `human.ts`: меню с галочками (`PromptIO.checkbox`), ответ автопилота — исходные галочки.
- Новый `run-settings.ts`: роли и их обязательность, разбор `--skip-roles`, настройки по умолчанию —
  чистые функции для unit-тестов.
- `state.ts`: `options.skip` — выключенные роли.
- `report.ts`: раздел «Настройки прогона» в `ACCEPTANCE.md`.
- `context-builder.ts`: промпт финального ревью без отчёта acceptance, если acceptance-tester выключен.
- README и AGENTS.md: диалог настроек, флаг, пропуск шагов.
- Новых зависимостей нет: `@inquirer/checkbox` уже входит в `@inquirer/prompts`.

# Design

## Context

Вопросы с вариантами приходят от spec-author в двух местах: ответ шага уточнений (`stageClarify`,
вопросы живут только в памяти до ответа) и `questions` в ответе автора артефакта (`collectQuestions`
→ `state.spec.questions`). Человек отвечает на них через `Human.question` в трёх местах:
`stageClarify`, `artifactGate` (отложенные вопросы по артефакту), `stageApproval` (оставшиеся
вопросы перед freeze). `Human.question` строит `select` из вариантов, добавляет «Свой ответ…» и
возвращает строку — label варианта или введённый текст.

Роли вызываются через `callRole`: повторы на сбоях CLI, после их исчерпания — `infraExhausted`
с диалогом. Режим только на чтение (`readOnly`) уже есть у шага уточнений, его ACL отклоняет
запись и shell. Сторож простоя и диалог вмешательства подключаются через `interventionHandler`,
а решение «остановить» превращается в `Blocked` в `afterIntervention`.

## Goals / Non-Goals

**Goals:**
- Цикл обсуждения внутри `Human.question` без знания о ролях: реплику выполняет переданная функция.
- Цикл проверяется unit-тестами без TTY и моделей, а mock-прогоном — целиком через сессию роли.

**Non-Goals:**
- Потоковый вывод ответа роли по мере генерации: ответ печатается целиком после сессии, а ход
  сессии виден в обычных строках роли и в панели.
- Ограничение длины переписки в промпте: при лимите в 5 реплик она невелика (см. риски).

## Decisions

### 1. Цикл в `human.ts`, реплика — функция контроллера

`Human.question(q, discuss?)` получает необязательный объект обсуждения:

```ts
interface DiscussTurn { at: string; message: string; answer: string; optionsChanged?: boolean }
interface DiscussReply { answer: string; options?: QuestionOption[]; recommended?: number; rationale?: string }
interface Discuss {
  history: DiscussTurn[];                 // уже сохранённая переписка (resume)
  limit: number;                          // limits.discussTurns, 0 — без диалога лимита
  reply(message: string, history: DiscussTurn[], q: QuestionView): Promise<DiscussReply | { error: string }>;
  onTurn(turn: DiscussTurn, q: QuestionView): void;   // сохранить вопрос и переписку
  autoMessage?: string;                   // inject discuss-question: реплика без человека
}
```

и возвращает `{ answer: string; discussion: DiscussTurn[] }`. Без `discuss` пункта «Обсудить» нет,
и поведение прежнее, поэтому меню вопроса больше нигде не меняется.

Цикл: показать меню. «Обсудить» → `input`, пустой текст → снова меню. Иначе `reply`; ошибка →
`log.warn` с причиной и снова меню. Успех → печать ответа, при допустимых `options` замена
вариантов, рекомендации и обоснования (и строка «варианты обновлены»), `onTurn`, снова меню.
Диалог лимита — обычный `select`, когда `history.length > 0`, `history.length % limit === 0` и для
этого числа реплик продолжение ещё не подтверждено. Так счёт переживает resume без отдельного
поля, а после «продолжить» следующий диалог будет через `limit` реплик.

Альтернатива — цикл в контроллере вокруг `Human.question`. Отказались: меню, ввод и повтор меню —
забота `Human`, а контроллеру пришлось бы разбирать пункт «Обсудить» в трёх местах.

Для тестов `Human` получает необязательный второй аргумент конструктора `io = { select, input, tty }`
(по умолчанию — `@inquirer/prompts` и `process.stdin.isTTY`). Unit-тесты подают сценарий ответов
меню и ввода и заглушку `reply`.

### 2. Реплика — одна сессия роли через `runRole`, без серии повторов

В `controller.ts` функция `discussFor(ctx, q, where)` собирает `Discuss`. Её `reply` пишет контекст
(`writeContext`, метка `discuss-<id>-<n>`), вызывает `runRole` с `readOnly: true`,
`meta.kind = 'discuss'`, обработчиком вмешательства и затем делает `account` и `checkMcp`.
Решение «остановить» по-прежнему бросает `Blocked` через `afterIntervention`. Любой другой
неуспех (сбой CLI, «повторить шаг», пустой ответ) возвращает `{ error }`.

`callRole` не используется: его повторы и `infraExhausted` хороши для шага конвейера, а здесь
человек ждёт ответа перед меню. Повторить он может сам, снова выбрав «Обсудить», а
диалог исчерпания посреди вопроса только запутает.

Отвечает роль из `q.from` (у вопросов шага уточнений — `spec-author`). Каждая реплика — новая
сессия: переписка целиком в промпте, как требует «Отдельная сессия на вызов», без resume
сессии автора. Каждая реплика записывается `store.loop('discuss:<id>', n, 'REPLY' | 'ERROR', note)`.

### 3. Промпт и разбор ответа в `context-builder.ts`

`discussPrompt(base, d)` — заголовок шага «обсуждение вопроса», intent с уточнениями, вопрос,
`why`, варианты с описаниями и текущей рекомендацией, файлы артефакта (для вопросов по артефакту;
прочитать их сами), переписка и новая реплика человека. Правила: шаг только на чтение; ответить на
реплику по существу, со ссылками на файлы, если нужно; не решать за человека; менять варианты,
только если обсуждение показало, что они неполны или неточны. Формат ответа:

```json
{"answer":"...","options":[{"label":"...","description":"..."}],"recommended":0,"rationale":"..."}
```

`options`, `recommended` и `rationale` необязательны. `parseDiscussReply(text, current)` — чистая
функция: JSON с непустым `answer` берётся как есть. Без JSON весь текст без обрамления кода —
это `answer`. Пустой `answer` — ошибка. Варианты принимаются при 2–6 непустых label,
`recommended` вне диапазона → 0. Недопустимые варианты молча отбрасываются, остаются прежние.

### 4. Хранение и передача автору

- `Question` в `state.ts` получает `discussion?: DiscussTurn[]`. Для вопросов из `state.spec.questions`
  `onTurn` обновляет `options`/`recommended`/`rationale`/`discussion` и сохраняет `store.save()`
  после каждой реплики. Это даёт resume посреди обсуждения.
- Вопросы шага уточнений до ответа в `state.json` не попадают (как сейчас). Переписка уходит в
  `intent.clarifications[i].discussion` (новое необязательное поле), а `intentBlock` выводит её под
  ответом. Обрыв посреди уточнений повторяет шаг уточнений целиком, как и раньше.
- В находку человека (`artifactGate`, `stageApproval`) переписка добавляется к тексту
  `Решение человека по вопросу …` блоком «Обсуждение». Ответ роли в нём обрезается до 1500 символов.
- `decisions`: в `comment` добавляется `· обсуждение: N реплик`, если N > 0. Ответы шага уточнений
  теперь тоже пишутся в `decisions` (gate `clarify`), чтобы отчёт приёмки показал и их.
  `report.ts` уже выводит `comment` и не меняется: число реплик приходит в тексте.

### 5. Вывод

Сессия реплики идёт вне `paused()`: панель и строки роли видны как у любого шага. Ответ печатается
блоком: `log.human` с заголовком `<роль> отвечает:` и строками ответа, затем снова меню. В контекст
меню добавляется строка `обсуждение: N реплик`.

### 6. Mock и fault injection

- `TaskMeta.kind` получает `'discuss'`, а `describeTask` — «обсуждение вопроса <id>». Добавляется
  `meta.discuss = { id, options, recommended }`.
- Mock-роль на `discuss` отвечает JSON. В `answer` пересказана реплика, `options` — те же варианты,
  у рекомендуемого описание дополнено «(уточнено в обсуждении)», `recommended` прежний. Так
  проверяется путь обновления вариантов, а выбор автопилота не меняется.
- Точка `discuss-question` (в `INJECT_ALL`): контроллер берёт её (`ctx.inject.take`) на первом
  вопросе с вариантами и передаёт `autoMessage: 'Чем варианты отличаются для вызывающего кода?'`.
  `Human` с `autoMessage` выполняет одну реплику до меню, даже при `--auto-approve`, затем
  работает как обычно. В mock-прогоне это вопрос шага уточнений.

### 7. Policy

`limits.discussTurns` (по умолчанию 5, `0` — без диалога лимита) в `policy.ts` и
`.agentflow/policy.yaml` с комментарием.

### Проверка mock-прогоном

В копии kit: `npm run agentflow -- run tasks/01-slugify.md --mock --auto-approve --inject all`
завершается кодом 0 и принимает change. В выводе есть `▶ субагент spec-author` с видом
«обсуждение вопроса», `spec-author отвечает:`, «варианты обновлены», а затем
`(--auto-approve) → Отбрасывать`. В `events.jsonl` есть `loop` `discuss:clarify-1` с `REPLY`.
В `ACCEPTANCE.md` у решения `clarify` стоит «обсуждение: 1 реплика». Интерактивный цикл (ввод,
лимит, сбой) проверяется unit-тестами `Human` со сценарием `io`.

## Risks / Trade-offs

- [Реплика стоит целой сессии роли: пара минут и токены на чтение файлов] → режим только на чтение,
  `maxTurns` роли, лимит реплик с диалогом. Человек видит ход сессии в панели.
- [Длинная переписка раздувает промпт и находку] → лимит 5 по умолчанию, обрезка ответа в находке.
  Промпт реплики несёт переписку полностью: роли нужен контекст.
- [Роль меняет варианты без причины] → изменение явно отмечено в логе, а прежние варианты видны в
  переписке. Окончательно выбирает всё равно человек.
- [Вопросы шага уточнений не переживают обрыв посреди обсуждения] → как и сейчас: шаг уточнений
  повторяется целиком. Хранить их ради этого — отдельное изменение.
- [`autoMessage` под `--auto-approve` запускает роль без человека] → только при явной точке inject.

# Рубрика: specs

## Обязательные проверки

- `SPECS-TRACE` — для каждой capability из proposal есть файл specs/<capability>/spec.md, лишних нет.
- `SPECS-SCENARIOS` — у каждого требования есть хотя бы один сценарий WHEN/THEN, включая негативный там, где вход может быть некорректным.
- `SPECS-TESTABLE` — каждый THEN проверяем снаружи: конкретное значение, ошибка или наблюдаемое поведение.
- `SPECS-NO-IMPL` — нет имён внутренних функций, библиотек и шагов реализации, кроме публичного API.

## На что ещё смотреть

- Одно поведение на требование; нормативные SHALL/MUST.
- Требования не противоречат друг другу и proposal.
